# GUI 扫描触发采用丢弃式 single-flight

Scan 有多个触发入口（手动重扫、孤儿/残留处置后的自动重扫），并发触发会产生双倍全量 IO、重复的历史快照记录（趋势图出现重复点）以及多个 `scan:done` 事件。决定采用丢弃语义：扫描已在进行中时，新的触发立即返回、不排队——进行中的那轮扫描结束时自然会刷新界面（前端依赖 `scan:done` 事件，无需感知被合并的请求）。代价是扫描启动瞬间发生的目录变化要等下一次触发才可见，对以分钟为粒度的磁盘占用场景可接受；排队再跑一轮则可能让处置后的界面长时间停留在"扫描中"，且相邻两次触发间隔通常小于扫描时长，收益不成比例。

## Considered Options

- 丢弃（已选）：实现最小，行为可预测。
- 排队：最新触发结束后再跑一轮，时效性好但会把重复扫描串成链，双倍 IO 变成 N 倍。
- 合并去抖：把密集触发合并为一次延迟执行，引入定时器复杂度，对本场景过度设计。
