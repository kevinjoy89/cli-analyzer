## CLI Analyzer v0.4.2 — 双形态版本可读、批量清理可配置

### 新功能

- **双形态版本分行展示**：同一个工具可以有两种形态，各自有版本。kimi 的 CLI 是 2.1.0、桌面端是 1.0.2，过去只显示其中一个且无从判断是哪个；现在版本列直接分两行列 `CLI 2.1.0` / `桌面端 1.0.2`，是否一致一眼可见
- **批量清理范围可配置**：`config.json` 新增 `clean.bulkKinds`（追加）与 `clean.bulkExclude`（剔除），最终范围 = `(内置默认 ∪ bulkKinds) − bulkExclude`。用户规则包声明的自定义 Kind 从此能进 `clean --all`——此前规则包只能影响归因，永远进不了批量处置
- **路径 `~` 简写**：`/Users/you/Library/Application Support/JoyCoder` 过去在回收站列表里被截断成 `/Users/you/Library/Application Supp...`，恰好切掉了标识目录的那一段；现在显示为 `~/Library/Application Support/JoyCoder`。悬停仍可看完整绝对路径

### 修复

- **五个 AI 工具版本显示「—」**：WorkBuddy / ZCode / Visual Studio Code 只有桌面端没有 PATH 二进制，`--version` 无处可探；现在从 `.app` 包的 `Info.plist` 读取版本。Kimi Code / mimocode 则是探测失败被永久缓存——缓存键是「路径+大小+修改时间」，一次并发超时就把空版本钉死到二进制变更为止。现在失败最多重试 3 次，偶发失败不会变成永久缺版本
- **探测条件用错字段**：跳过探测的判据是「版本非空」，但双形态工具的版本会先被桌面端版本填上，导致 CLI 版本永远不被探测（agy、kimi 因此长期只显示桌面版本）。判据改为「CLI 版本非空」
- **确认弹窗不解释项数差异**：勾选父目录和它内部的子目录时，弹窗显示「确认处置 1 项」，却没说明另一项去哪了——数字是对的（子目录随父目录一起删除），但读起来像丢数据。现在弹窗列出全部勾选项，被包含的那项淡化并标注「随上级目录一起处置」，底部说明实际处置几项
- **`clean --json` 违反自身契约**：批量选择为空、或完全没有可处置项时，两条提前退出的分支输出的是纯文本而非 JSON，脚本拿到后解析失败。现在两条分支都输出空报告
- **`upgrade` / `residue` 未接入 CLI 分发**：这两个子命令加进来了，但 `main.go` 的分发白名单没同步，执行 `cli-analyzer upgrade run x` 会弹出 GUI 窗口而不是执行命令

### 破坏性变更

- **`clean` 报告的 `skipped` 结构改变**：从字符串数组（原因内嵌在 `"<路径> (原因)"` 里）变为对象数组 `{id, path, reason, message}`。`reason` 是稳定码（`subsumed` / `unknown-item` / `not-absolute` / `dirty-path` / `forbidden-root` / `trash-root` / `current-version` / `not-inside-parent`），`message` 是本地化文案。`schemaVersion` 由 1 升至 2
  - 影响：任何读取 `clean --json` 的脚本需要适配。例如 `jq '.skipped[]'` 现在拿到的是对象而非字符串

### 改进

- **契约快照只报差异行**：契约结构测试失败时不再整份打印 60 行相同文本，只列出「快照有而输出没有」与「输出有而快照没有」的行
- **测试跨平台加固**：修正了一批只在 macOS 成立的测试假设（Unix 绝对路径、`.app` 版本读取、CRLF 换行符），Windows 与 Linux 的 CI 现在真正能跑通
- **新增本地 CI 复现脚本**：`scripts/verify-ci-local.sh` 一条命令复现 CI 的 test job 全部步骤

## English

**CLI Analyzer v0.4.2** — readable dual-form versions, configurable bulk cleanup.

### New

- **Dual-form versions shown on separate lines**: a tool can exist in two forms, each with its own version. kimi's CLI is 2.1.0 while its desktop app is 1.0.2; the UI used to show one of them with no way to tell which. The version column now lists `CLI 2.1.0` and `Desktop 1.0.2` on two lines, so whether they match is immediately visible
- **Configurable bulk-clean scope**: `config.json` gains `clean.bulkKinds` (add) and `clean.bulkExclude` (remove); the final set is `(built-in ∪ bulkKinds) − bulkExclude`. Kinds declared by your own rule packs can now participate in `clean --all` — previously a rule pack could only influence attribution, never bulk disposal
- **`~` path shorthand**: `/Users/you/Library/Application Support/JoyCoder` was truncated to `/Users/you/Library/Application Supp...` in the trash list, cutting off exactly the part that identifies the directory. It now reads `~/Library/Application Support/JoyCoder`; hovering still reveals the absolute path

### Fixes

- **Five AI tools showed "—" for their version**: WorkBuddy / ZCode / Visual Studio Code have only a desktop app and no PATH binary, so `--version` had nothing to run; the version is now read from the bundle's `Info.plist`. Kimi Code and mimocode failed differently — their probe failures were cached forever (the cache key is path+size+mtime), so a single concurrent timeout pinned an empty version until the binary itself changed. Failures are now retried up to 3 times, so a transient failure no longer becomes a permanent gap
- **Probe skip condition used the wrong field**: the check was "version is non-empty", but for dual-form tools the desktop version fills that field first, so the CLI version was never probed (this is why agy and kimi kept showing only the desktop number). The condition is now "CLI version is non-empty"
- **Confirm dialog didn't explain a count mismatch**: checking a parent directory and a directory inside it showed "dispose of 1 item" without saying where the other went. The number was right — the child is deleted along with its parent — but it read like data loss. The dialog now lists every checked item, dims the subsumed one with a "disposed with the parent directory" note, and states how many items will actually be disposed of
- **`clean --json` violated its own contract**: on two early-exit branches (empty batch selection, or nothing cleanable at all) it printed plain text instead of JSON, so scripts failed to parse it. Both branches now emit an empty report
- **`upgrade` / `residue` missing from CLI dispatch**: the subcommands existed but `main.go`'s whitelist was never updated, so `cli-analyzer upgrade run x` opened the GUI window instead of running the command

### Breaking change

- **`clean` report's `skipped` changed shape**: from a string array (reason embedded as `"<path> (<reason>)"`) to an array of objects `{id, path, reason, message}`. `reason` is a stable code (`subsumed` / `unknown-item` / `not-absolute` / `dirty-path` / `forbidden-root` / `trash-root` / `current-version` / `not-inside-parent`); `message` is the localized text. `schemaVersion` goes from 1 to 2
  - Impact: any script reading `clean --json` needs updating. For example `jq '.skipped[]'` now yields objects rather than strings

### Improved

- **Contract snapshots report only the diff**: a failing contract structure test no longer dumps 60 lines of identical text; it lists only the lines present in the snapshot but not emitted, and vice versa
- **Cross-platform test hardening**: fixed a batch of assumptions that only held on macOS (Unix absolute paths, `.app` version reading, CRLF line endings), so the Windows and Linux CI jobs now genuinely pass
- **Local CI reproduction script**: `scripts/verify-ci-local.sh` replays the CI test job in one command
