## CLI Analyzer v0.4.0 — 自升级命令探测与 GUI 升级入口

### 新功能

- **自升级子命令探测**：无包管理器来源的工具（versioned/other/local-bin）现在会探测 `<bin> -h`（失败回退 `--help`）里的官方自升级命令（claude update / uv self update / kimi upgrade…），探测到即可一键代跑升级，不再只能看提示文案
- **GUI 升级按钮**：工具详情页仅当该工具有官方升级命令时显示「升级」按钮；探测结果按 real path + size + mtime 缓存，详情页反复渲染不重跑子进程；二进制变更后自动失效重探

### 修复

- **Windows `.cmd`/`.bat` 脚本直跑**：卸载/升级代跑与 `-h` 探测统一经 `cmd.exe /c` 执行（Go 的 CreateProcess 不解析脚本）——Windows 上脚本入口的工具（如 claude.exe shim）可正确探测与卸载
- **Windows 探测兼容**：`-h`/`--help` 单命令 3s 超时，PATH 增强后解析；命令解析结果按 PATHEXT 枚举大小写归一化（大小写不敏感比较）

### 改进

- 探测负结果（无自升级子命令/探测失败）也缓存，二进制不变不重复跑子进程

## English

**CLI Analyzer v0.4.0** — self-upgrade command probing & GUI upgrade entry.

### New

- **Self-upgrade subcommand probing**: tools without a package-manager source (versioned / other / local-bin) now probe `<bin> -h` (falling back to `--help`) for an official self-upgrade subcommand (claude update / uv self update / kimi upgrade…). When detected, upgrade can be run with one click instead of just showing hint text
- **GUI upgrade button**: the tool detail view shows an "Upgrade" button only when the tool has an official upgrade command; probe results are cached by real path + size + mtime, so re-rendering never re-spawns the child process, and a binary change invalidates the cache automatically

### Fixes

- **Windows `.cmd`/`.bat` script execution**: uninstall/upgrade run-bypass and `-h` probing now execute scripts via `cmd.exe /c` (Go's CreateProcess can't parse scripts) — script-entry tools on Windows (e.g. the claude.exe shim) are probed and uninstalled correctly
- **Windows probing compatibility**: single-command 3s timeout for `-h`/`--help`, resolution with an augmented PATH; command resolution compares the PATHEXT extension case-insensitively

### Improved

- Negative probe results (no self-upgrade subcommand / probe failure) are cached too — the child process is not re-spawned while the binary is unchanged
