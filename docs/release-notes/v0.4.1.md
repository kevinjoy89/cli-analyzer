## CLI Analyzer v0.4.1 — AI 工具编目、友好展示名与占用口径修正

### 新功能

- **AI 工具编目**：内置 AI 编码工具目录（agent / AI IDE 两类），条目按语义标注数据种类——会话记录、会话数据库、代码索引、遥测、日志、工作区数据等，占用一目了然
- **AI 优先分组列表**：工具列表拆成「AI 编码工具」（默认展开、置顶）与「其他 CLI 工具」（默认折叠、显示条数与合计占用）。此前 295 行把 16 个 AI 条目彻底埋掉；搜索同时过滤两段，关键词只命中「其他」时自动展开
- **已卸载标注**：无二进制且桌面端宿主缺失的 AI 条目显示红色「已卸载」徽章——数据残留照样列出，但不再假装是活跃工具
- **会话数据库仅报告**：会话库（`*.db` / `*.sqlite` 及 wal/shm）会被归因展示，但**永不进入清理计划**——删掉就等于丢掉历史会话；树下钻中这类子项不可勾选并附说明
- **双形态占用拆分**：同时有 CLI 与桌面端形态的条目（opencode、codex、dsh、kimi、agy…）详情页新增形态小计，桌面端与 CLI 各占多少分得清
- **友好展示名**：条目可带展示名（claude → Claude Code、code → Visual Studio Code、agy → Antigravity、codex → Codex CLI…），CLI 表格、GUI 列表与详情页优先展示，搜索也命中

### 修复

- **可处置合计父子重复计数**：AI 条目的父子目录规则（如 `.kimi-code` 与 `.kimi-code/bin`）此前被简单相加，同一批字节算两遍——出现「可处置 > 总占用」（marscode 7.9G vs 3.9G、kimi 940MB vs 556MB），安装占用被压成 0 导致列空白。现在按极大路径求和，保证可处置 ≤ 总占用；清理时被完全包含的路径自动跳过，不再重复删除报错
- **claude 安装基数误判**：`~/.local/share/claude`（617M，含 versions/）被当成可清理数据，安装占用凭空消失，且 `clean --include-data --all` 可能清掉正在使用的安装。已改为安装类型，旧版本清理仍由版本派生规则负责
- **桌面端安装包未计量**：`/Applications` 下的 Electron 应用此前不计入安装占用，明明装着的工具显示 0 B。现在归因声明的 `.app` 包会计入安装与总占用（实测 workbuddy 1076M、codex 1462M）；已卸载工具的缺失应用包不计，与「已卸载」标注一致
- **GUI 并发与数据层加固**：并发触发扫描不再重复扫描/重复记历史/重复发事件；探测改为锁内快照，消除数据竞争；`history.db` 损坏自动备份重建；更新弹窗动态值转义
- **无安装根的工具显示「—」**：不再用误导性的 0 B

### 改进

- **已卸载且零占用的条目不显示**：仅剩 0 字节残留（或已在内置回收站中清空）的已卸载工具不再占用列表；缺失的可处置项在空工具判定前剪枝
- **工具名自适应列宽**：名称列改为弹性宽度并省略号截断，类别/已卸载徽章不换行
- **类别徽章配色**：agent 蓝色、AI IDE 紫色，两段一眼区分
- **默认 `--all` 批量计划纳入 AI 安全项**：索引、遥测、日志进入默认保护性清理（可再生缓存与纯日志垃圾）；运行时、会话、插件、产物、检查点、工作区数据仍需 `--include-data`
- **新增 AI IDE 条目**：JoyCoder、CodeBuddy 从 VS Code 的扩展伴侣目录拆为独立条目；Gemini 条目并入 agy（Antigravity，CLI 数据实际位于 `~/.gemini`）

## English

**CLI Analyzer v0.4.1** — AI tool catalog, friendly display names, and corrected occupancy math.

### New

- **AI tool catalog**: a built-in catalog of AI coding tools (agent / AI IDE) with semantic data kinds — sessions, session DB, code index, telemetry, logs, workspace data — so each entry's footprint is readable at a glance
- **AI-first grouped list**: the tool list splits into "AI coding tools" (expanded, on top) and "Other CLI tools" (collapsed by default, showing count + total footprint). 295 rows used to bury the 16 AI entries entirely; search filters both sections and auto-expands "others" when only that section matches
- **Uninstalled badge**: AI entries with no binary and no desktop host are marked with a red "uninstalled" badge — residue is still listed, but no longer pretends to be an active tool
- **Session databases are report-only**: session stores (`*.db` / `*.sqlite` plus wal/shm) are attributed and displayed but **never enter a cleanup plan** — removing them destroys resume history; such children are non-selectable in the drill-down with an inline note
- **Form-factor occupancy split**: entries that have both CLI and desktop forms (opencode, codex, dsh, kimi, agy…) get a per-form subtotal in the detail page, so desktop vs CLI consumption is no longer merged into one number
- **Friendly display names**: entries may carry a display name (claude → Claude Code, code → Visual Studio Code, agy → Antigravity, codex → Codex CLI…), preferred in the CLI table, GUI list and detail panel, and matched by search

### Fixes

- **Parent/child double counting in cleanable totals**: parent and child directory rules on AI entries (e.g. `.kimi-code` and `.kimi-code/bin`) were summed naively, counting the same bytes twice — producing "cleanable > footprint" (marscode 7.9G vs 3.9G, kimi 940MB vs 556MB) and clamping install bytes to 0, which blanked the column. Totals now sum maximal paths only, guaranteeing cleanable ≤ footprint; fully contained paths are skipped on cleanup instead of being deleted twice and erroring
- **claude install base misclassified**: `~/.local/share/claude` (617M, holding versions/) was attributed as cleanable data, making install bytes vanish and letting `clean --include-data --all` trash a live install. It is now install-kind; old-version cleanup still comes from the version derivation rules
- **Desktop app bundles not measured**: Electron apps under `/Applications` were never counted, so clearly installed tools showed 0 B. Declared `.app` bundles now count toward install and footprint (measured: workbuddy 1076M, codex 1462M); missing bundles for uninstalled tools stay unattributed, consistent with the badge
- **GUI concurrency and data-layer hardening**: concurrent scan triggers no longer double-scan, double-record history, or emit duplicate events; probing uses a lock-held snapshot, removing a data race; a corrupt `history.db` is backed up and rebuilt; dynamic values are escaped in the update modal
- **"—" instead of a misleading 0 B** for tools without any install root

### Improved

- **Uninstalled tools with zero footprint are hidden**: entries left with 0-byte residue (or already emptied into the built-in trash) no longer occupy the list; missing cleanables are pruned before the empty-tool check
- **Flexible tool-name column**: the name column is now flexible-width with ellipsis truncation, and category/uninstalled badges no longer wrap
- **Category badge colors**: agent blue, AI IDE violet — the two segments read at a glance
- **Default `--all` batch plan includes AI-safe kinds**: index, telemetry and logs join the protective default (regenerable caches and pure log waste); runtime, sessions, plugins, artifacts, checkpoints and workspace data still require `--include-data`
- **New AI IDE entries**: JoyCoder and CodeBuddy split out of VS Code's extension companion dirs into standalone entries; Gemini folded into agy (Antigravity), since its CLI data actually lives in `~/.gemini`
